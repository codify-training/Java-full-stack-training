1. WHAT IS GIT?
====================================================================

Git is a version control system that allows you to:
- Track changes to your code over time
- Work collaboratively with others
- Maintain a complete history of your project
- Switch between different versions of your code
- Manage multiple features in parallel (branches)

Think of it as a "save" system for your entire project with detailed history.

====================================================================
2. KEY CONCEPTS
====================================================================

📌 REPOSITORY (REPO)
   - A folder that contains your project and Git history
   - Can be local (on your computer) or remote (on GitHub, GitLab, etc.)

📌 COMMIT
   - A snapshot of your code at a specific point in time
   - Contains changes made to files + a message describing those changes
   - Acts like a checkpoint you can return to

📌 BRANCH
   - A separate line of development
   - Main branch: Usually called "main" or "master"
   - Feature branch: A branch for developing specific features

📌 STAGING AREA
   - A holding area for changes you want to commit
   - Allows you to choose which files to include in a commit

📌 REMOTE
   - A version of your repository hosted on the internet (GitHub, GitLab, Bitbucket)
   - Allows collaboration and backup

📌 MERGE
   - Combining changes from one branch into another
   - Usually done when a feature is complete

3. INSTALLATION & SETUP
====================================================================

⚙️ INSTALL GIT
   - Windows: Download from https://git-scm.com/
   - Mac: Use Homebrew or download from git-scm.com
   - Linux: sudo apt-get install git

✅ VERIFY INSTALLATION
   Command: git --version
   (Should show version number like "git version 2.40.0")

⚙️ INITIAL CONFIGURATION
   Set your name:
   git config --global user.name "Your Name"

   Set your email:
   git config --global user.email "your.email@example.com"

   Verify configuration:
   git config --global --list

4. BASIC COMMANDS
====================================================================

🔧 INITIALIZING A REPOSITORY

   Create a new Git repository in current folder:
   git init

   Clone an existing repository from GitHub:
   git clone https://github.com/username/repo-name.git


🔧 CHECKING STATUS

   See status of all files (modified, untracked, staged):
   git status

   View detailed changes in files:
   git diff


🔧 STAGING & COMMITTING

   Stage specific file:
   git add filename.txt

   Stage all changes:
   git add .

   Stage all changes in a folder:
   git add foldername/

   Unstage a file (remove from staging):
   git restore --staged filename.txt

   Commit staged changes with a message:
   git commit -m "Your commit message"

   Commit with detailed message (opens text editor):
   git commit

   Combine staging and committing (only for modified files):
   git commit -am "Your commit message"


🔧 VIEWING HISTORY

   View commit history (most recent first):
   git log

   View commit history in one line per commit:
   git log --oneline

   View last 5 commits:
   git log -5

   View who changed each line:
   git blame filename.txt


🔧 PUSHING & PULLING

   Push commits to remote repository:
   git push

   Push to specific branch:
   git push origin branch-name

   Pull latest changes from remote:
   git pull

   Fetch changes without merging:
   git fetch

5. WORKING WITH BRANCHES
====================================================================

🌿 VIEW BRANCHES

   List all local branches:
   git branch

   List all branches (local & remote):
   git branch -a

   View current branch:
   (Shows with asterisk (*) in git branch output)


🌿 CREATE & SWITCH BRANCHES

   Create a new branch:
   git branch branch-name

   Switch to a branch:
   git checkout branch-name

   Create AND switch to a new branch:
   git checkout -b branch-name
   OR
   git switch -c branch-name

   Rename a branch:
   git branch -m old-name new-name

   Delete a branch:
   git branch -d branch-name

   Force delete:
   git branch -D branch-name


🌿 MERGE BRANCHES

   Merge another branch into current branch:
   git merge branch-name

   Example workflow:
   1. git checkout main           (Switch to main)
   2. git merge feature-branch    (Merge feature-branch into main)
   3. git branch -d feature-branch (Delete feature-branch)

6. WORKFLOWS
====================================================================

📊 WORKFLOW 1: PUSHING CODE TO EXISTING BRANCH

   1. Make changes to your files
   2. Check status: git status
   3. Stage changes: git add .
   4. Commit: git commit -m "description of changes"
   5. Push to GitHub: git push origin branch-name
      (or just: git push)


📊 WORKFLOW 2: STARTING A NEW PROJECT & PUSHING TO GITHUB

   1. Create folder: mkdir my-project
   2. Navigate: cd my-project
   3. Initialize: git init
   4. Add files and make changes
   5. Stage: git add .
   6. Commit: git commit -m "Initial commit"
   7. Create repo on GitHub
   8. Connect to remote:
      git remote add origin https://github.com/username/repo-name.git
   9. Rename branch to main:
      git branch -M main
   10. Push to GitHub:
      git push -u origin main


📊 WORKFLOW 3: WORKING WITH A FEATURE BRANCH

   1. Start from main: git checkout main
   2. Create feature branch: git checkout -b feature/login-page
   3. Make changes
   4. Commit: git commit -m "Add login page"
   5. Push: git push -u origin feature/login-page
   6. Create Pull Request on GitHub
   7. After approval, merge to main
   8. Delete feature branch: git branch -d feature/login-page


📊 WORKFLOW 4: CLONING & CONTRIBUTING TO EXISTING PROJECT

   1. Clone repository: git clone https://github.com/user/project.git
   2. Navigate: cd project
   3. Create feature branch: git checkout -b feature/my-feature
   4. Make changes
   5. Commit: git commit -m "Add my feature"
   6. Push: git push origin feature/my-feature
   7. Create Pull Request on GitHub

7. COMMON SCENARIOS
====================================================================

❓ "I made changes but don't want to commit them yet"
   git stash           (Save changes temporarily)
   git stash pop       (Restore saved changes)


❓ "I want to commit only some of my changes"
   git add filename1.txt filename2.txt  (Add specific files)
   git commit -m "Specific changes"


❓ "I forgot what I changed"
   git diff            (Show unstaged changes)
   git diff --staged   (Show staged changes)


❓ "I want to see who wrote this line of code"
   git blame filename.txt  (Shows author and commit for each line)


❓ "I need to switch branches but have uncommitted changes"
   Option 1: Commit changes first
   Option 2: Stash: git stash, switch branch, then: git stash pop

8. UNDOING CHANGES
====================================================================

⚠️  DISCARD CHANGES IN WORKING DIRECTORY

   Discard changes in one file:
   git restore filename.txt

   Discard all changes:
   git restore .


⚠️  REMOVE FILES FROM STAGING

   Remove from staging (keep changes):
   git restore --staged filename.txt

   Remove all from staging:
   git restore --staged .


⚠️  UNDO LAST COMMIT

   Keep changes (undo commit only):
   git reset --soft HEAD~1

   Discard commit and changes:
   git reset --hard HEAD~1

   Create a new commit that undoes changes:
   git revert HEAD


⚠️  FIX LAST COMMIT MESSAGE

   git commit --amend -m "New message"

9. COLLABORATION
====================================================================

👥 PULLING LATEST CHANGES

   Always pull before starting work:
   git pull

   This prevents conflicts with others' work


👥 HANDLING MERGE CONFLICTS

   When pulling causes conflicts:
   1. Edit the conflicted files
   2. Remove conflict markers (<<<, ===, >>>)
   3. git add conflicted-files
   4. git commit -m "Resolve merge conflicts"
   5. git push


👥 KEEPING YOUR BRANCH UP-TO-DATE

   Pull latest from main while on feature branch:
   git fetch origin
   git rebase origin/main
   git push -u origin feature-branch


👥 CREATING A PULL REQUEST (On GitHub)

   1. Push your feature branch
   2. Go to GitHub repository
   3. Click "Compare & pull request"
   4. Add description of changes
   5. Request reviewers
   6. Submit Pull Request
   7. Address feedback if needed
   8. Merge when approved

10. BEST PRACTICES
====================================================================

✅ DO:
   ✓ Commit often (many small commits, not few large ones)
   ✓ Write clear, descriptive commit messages
   ✓ Pull before starting work
   ✓ Create separate branches for features
   ✓ Review changes before committing (git diff)
   ✓ Use meaningful branch names (feature/login, fix/header-bug)
   ✓ Sync with main regularly to avoid conflicts
   ✓ Delete old branches after merging


❌ DON'T:
   ✗ Commit large binary files or sensitive data
   ✗ Force push to shared branches
   ✗ Write vague messages like "update" or "fix stuff"
   ✗ Leave unfinished work committed
   ✗ Work directly on main branch
   ✗ Ignore merge conflicts
   ✗ Forget to pull before starting work


📝 GOOD COMMIT MESSAGES

   ✓ Good:   "Add user authentication form"
   ✗ Bad:    "update code"

   ✓ Good:   "Fix login button not responding to clicks"
   ✗ Bad:    "fix bug"

   ✓ Good:   "Update dependencies and remove deprecated functions"
   ✗ Bad:    "stuff"
